# 強力右鍵

在網頁上選一段字 → 右鍵 → **存起來**。那段字連同來源網址、標題，變成本機的一個檔。

先亂存，整理是另一回事。

也可以 → 右鍵 → **改這段字**：直接把自己網站上的字改掉，不用開編輯器、不用叫 AI（見下面「改這段字」）。

腳本本身不存任何東西：它把字送給**你自己電腦上**的收件服務（這個 repo 裡的 `server.js`），
所以要用就得兩個都裝，東西只會留在你的硬碟。

```
選一段字 → 右鍵
  ┌──────────────────────────┐
  │ 存起來                    │
  │ 改這段字                  │
  │ Shift + 右鍵 = 原本的選單  │
  └──────────────────────────┘
                       右下角：已存 2026-11-15_001354_某篇文章.md
```

- 有選字才會出現；沒選字時右鍵完全不變。
- `Shift + 右鍵` 永遠是瀏覽器原本的選單。
- 檔案在 `文件\power-right-click`（可用 `DROP_DIR` 改）。

## 兩個零件

| | 是什麼 |
|---|---|
| `power-right-click.user.js` | 油猴腳本：蓋掉右鍵、畫選單、把選取的字送出去 |
| `server.js` | 收件服務：只聽本機 `127.0.0.1:4470`，收到就存檔。Node，零依賴 |

選單有哪些項目由收件服務決定（`src/actions.js` 那張清單）。加一個動作只要在那裡加一列，腳本不用動。

## 安裝

需要 Node 20 以上，瀏覽器裝好 Tampermonkey。

```bash
npm run init        # 產生 .env（隨機金鑰），已經有就不動
npm run autostart   # 放一個開機自動啟動的捷徑，並且現在就啟動
```

然後瀏覽器開 `http://127.0.0.1:4470/setup`：

1. 按「安裝腳本」，Tampermonkey 跳出來按安裝。
2. 回到設定頁按 `F5`，看到「已連上」就完成。金鑰是腳本自己從設定頁拿的，不用複製貼上。

不要自動啟動：`powershell -File scripts/autostart.ps1 -Remove`。只想手動跑：`npm start`。

## 改這段字

在自己的網站上選一段字 → 右鍵 → **改這段字** → 打新的字 → Enter。

```
┌──────────────────────────────┐
│ 原本  立即免費開始              │
│ 改成  [ 先用再說            ]   │
│              [取消]  [改]      │
└──────────────────────────────┘
畫面上的字當場變 · 左下角：已改 3 處，還沒送出 [送出]
```

- 收件服務拿那段字去你的專案資料夾找（預設是這個 repo 的上一層，裡面每個 git repo 都算；`RETEXT_ROOTS` 可改）。
  不用設定哪個網站是哪個專案：找得到就改，找不到就是改不了。改成功一次後它會記住這個網域是哪個專案。
- 每個網站第一次改會慢一點（要把所有專案找過一遍，幾秒到十幾秒），之後很快。
- 好幾處都有同一段字 → 列出檔名、行號讓你點一個。
- **送出** = 一個 commit（`chore: 網頁改字 N 處`）加 `git push`。你的站怎麼部署就照原本的方式部署。
- 改不了的情況：字是程式拼出來的、來自資料庫、選取跨了好幾個元素。這時它會把一句給 AI 的指令放進剪貼簿。
- 不會動的東西：有你還沒 commit 的修改的檔、壓縮過的檔、新的字裡多了可能弄壞程式的符號（`< > { }` 引號、反斜線）。
- 還沒有「放棄修改」：改錯就再改一次，或在那個專案裡 `git checkout -- 檔名`。

## 存下來的檔長這樣

```
---
source: https://example.com/some-article
title: 某篇文章
saved: 2026-11-14T16:13:54.737Z
---

你選的那段字。
```

檔名是 `時間_標題片段.md`，同名會自動加 `-2`，不會蓋掉舊的。

## 收件服務

| | | |
|---|---|---|
| `GET /health` | 不用金鑰 | 活著嗎 |
| `GET /menu` | 要金鑰 | 選單項目 |
| `POST /drop` | 要金鑰，JSON | `{ action, kind, text, url, title }` → 執行動作 |
| `POST /retext` | 要金鑰，JSON | `{ text, to, url, pick? }` → 在原始碼裡把字換掉 |
| `POST /retext/submit` | 要金鑰，JSON | `{ url }` → commit 加 push |
| `GET /retext/pending?host=` | 要金鑰 | 還沒送出幾處 |
| `GET /setup` | 只給本機直接開 | 設定頁 |
| `GET /power-right-click.user.js` | 不用金鑰 | 腳本本體（裡面沒有金鑰） |

金鑰用 `Authorization: Bearer <DROP_TOKEN>`。

設定（`.env` 或環境變數）：`DROP_TOKEN`（必填，沒有就不啟動）、`PORT`（4470）、`HOST`（127.0.0.1）、`DROP_DIR`、`RETEXT_ROOTS`（專案資料夾，多個用 `;` 分開）、`PRC_HOME`（改字的狀態檔放哪，預設 `~/.power-right-click`）。

### 為什麼設定頁這麼囉嗦

設定頁會把金鑰交出去，所以只在「這台電腦上的人直接打網址開」的時候才給：連線來自本機、
網址是 127.0.0.1 / localhost、沒有代理或 Cloudflare 加的標頭、不是別的網站嵌入或載入的。
之後如果把服務掛到對外的網域，設定頁照樣只有本機開得了。

`/drop` 只收 `application/json`：網頁可以偷偷跨站送 `text/plain`，但送 JSON 加金鑰標頭會被瀏覽器擋下來。

## 測試

```bash
npm test
```

涵蓋改字（單一命中、跨行、多處挑選、找不到、危險符號、送出與 push 失敗）、存檔內容、檔名安全（惡意標題跑不出資料夾）、金鑰、壞輸入、設定頁的各種拒絕情況。
腳本本體是用無頭瀏覽器手動驗的（選字 → 右鍵 → 點 → 檔案出現），還沒有放進 `npm test`。
